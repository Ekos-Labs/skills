# Contributing to Ekos Skills

Contributions should make a skill safer, clearer, easier to install, or more useful in real marketing work.

## Before opening a pull request

1. Work in one skill directory unless the change truly affects the collection.
2. Keep user approval before paid API calls, sending messages, publishing, or deleting data.
3. Label assumptions and preserve sources for factual claims.
4. Never include API keys, customer data, private prompts, or copyrighted assets.
5. Include the input used for testing and describe the resulting output.
6. Update `release.json` when requirements or behaviour change.

New skills need a `SKILL.md` and `release.json`. Keep the instructions agent-agnostic wherever possible.
